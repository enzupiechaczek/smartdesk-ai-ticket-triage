## How the results above were produced

These Actual values were recorded against the temporary stub predictor, which returned
technical with confidence 0.5 for every ticket. They are kept as the record for task 2915 and
they match the screenshots in this table. The trained model has since replaced the stub; the
rerun below is the current result. Neither set of numbers was adjusted to make a row pass.

predictor. Procedure: `python ai/train.py`, then `python backend/app.py`, then each input was
sent to POST /api/tickets. The local database was emptied first, so these ids are the real ones
from this run. Screenshots for this rerun have not been taken yet, so this table is documented

## Model quality, reported separately

Model accuracy is not a pass or fail condition for these rows and is tracked separately from the
API checks. The current model scores about 0.625 in cross-validation and mislabels some tickets,
for example TC-Priority-015 in the priority PR was classified billing for a printer problem. That
is a quality observation for the model owners, not an API bug.
